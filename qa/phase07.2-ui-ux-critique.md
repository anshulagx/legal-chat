# Phase 7.2 UI/UX critique

Recorded 2026-11-26 against baseline `ba22082e3597fe4e2fb6ceef2260e096b738b399`. Existing uncommitted phase-plan changes were present; this is a baseline observation, not a clean-checkout release verdict. UI source and built app inspected. No UI implementation was changed by this review.

## Method and evidence

Used Node 22.22.0, installed Chrome headless, isolated Playwright in `/tmp/legal-chat-phase072-tools`, and `scripts/phase05-harness.mjs` against disposable fictional records on the local `legalChatQA` replica set at port 27028. The harness creates and deletes its own random database. Customer and admin sessions were distinct fixture cookies, kept out of evidence. Test-only deterministic answer/retrieval adapters were used; these observations do not validate hosted model quality or direct S3 transfer.

Observed signup/login treatment through source, login in browser, fresh chat, a grounded cited long answer, source open/close, mobile history, a two-document comparison and file selection, and shared-document management. Numeric observations are in [phase07.2-ui-baseline.json](phase07.2-ui-baseline.json). Captures: [auth](phase07.2-before-auth.png), [fresh desktop](phase07.2-before-fresh-desktop.png), [long desktop](phase07.2-before-long-desktop.png), [long mobile](phase07.2-before-long-mobile.png), [mobile history](phase07.2-before-history-mobile.png), [comparison desktop](phase07.2-before-comparison-desktop.png), [comparison mobile](phase07.2-before-comparison-mobile.png), [source](phase07.2-before-source.png), [admin mobile](phase07.2-before-admin-mobile.png). No external UX claims are asserted here. The plan's evaluation criteria guide the review; observed behavior, source observations and design judgments are distinguished below. There was no human usability session, screen-reader walkthrough, native zoom observation or mobile software keyboard observation. Do not treat this document as an accessibility certification.

## Strengths to preserve

The observed cited-answer/source flow completed: opening a filename citation displayed “Exact cited passage”, and Escape closed the native source dialog. Source text, original-file link and document identity are visible together. This favors keeping the focused modal unless a side panel proves useful enough to justify its narrower reading area and extra responsive complexity.

The observed answer and comparison surfaces had no horizontal document overflow at 320, 390, 768 or 1280 CSS px for the bounded fixtures. The comparison stacks on mobile. File scope is explicitly called “Files in this chat”; ready status and limits are plain text. The comparison's missing-evidence side says no matching evidence rather than inventing a clause. These behaviors should survive redesign.

Fresh chat has an immediately identifiable question label and send action. Existing recovery paths distinguish failed/interrupted attempts and preserve questions; they need integrated replay on the redesigned candidate, not cosmetic replacement.

## Proposed direction for design review

Recommend one coherent direction: a restrained workspace shell, persistent compact composer, independent transcript scrolling, compact expandable attachment controls, ordered document identities, native focused source modal and an explicit admin destination. Retain the current legal-support green palette as a starting point; approve exact tokens in the design proposal. The evidence strongly supports making long-chat actions easier to reach and comparison identity explicit. It does not establish a user's preferred color, card style or information density.

Before UI implementation, review desktop/mobile mockups and state rules with Anshul as required by `Phase_7.2_Plan.md` step 7.2-C. No design approval is recorded here. The best next step to reduce uncertainty is reviewing the mockups using the measured long-answer and missing-comparison-side tasks, then validating those same tasks against the implementation.

## Limits and reproducibility

Baseline script was run with `/opt/homebrew/opt/node@22/bin/node /tmp/legal-chat-phase072-ui-review.mjs`; the script uses the repository harness, seeds a shared source beginning “Fictional agreement notice is 30 days.” followed by ten fictional review clauses, asks “What notice applies?”, measures `.composer`, opens the exact-source dialog and repeats viewport widths. It then seeds a private 30-day original and 60-day amendment, sends a selected two-version comparison, opens it from mobile history, and captures admin management with the separate fixture account. No production data or accounts are involved.

An initial unbounded 45-clause source exceeded what this deterministic answer fixture completed successfully within the browser wait. The final captures use ten clauses. That discarded attempt is not attributed to a product defect; it was not investigated enough to do so. The temporary browser tooling is not an application dependency. The saved screenshots and measurements are baseline evidence; independent final QA and accessibility observations remain required.
